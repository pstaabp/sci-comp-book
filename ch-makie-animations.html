    Section 16.2 Observables in Makie

    To make animations or interactive applications in julia, then it is important understand Observables, which are container objects that have values that can be updated and then plots or other interactives can react to the changes.
    🔗
    Before getting into complex interactives, let’s do a simple example. Define
    🔗
    x = Observable(0)
    and the result is
    x = Observable(0)
    🔗
    And if typeof(x) is run the result is Observable{Int64}, indicating that this is a parametric type (that is an Observable that can take Int64 values).
    🔗
    To change the value of x, we use index notation (like a vector) with an empty index as in
    🔗
    x[] = 5

    Note 16.5.

    If you use Observable, it is very important that you update values with the x[] syntax. If instead, you enter x = 5, then the variable x is replaced with a Int64 and not an observable.
    🔗
    🔗
    If you evaluate x, then you get Observable(5). This doesn’t seem very interesting.
    🔗

    Subsection 16.2.1 Observing Changing Observables

    The power of Observables is to react to a changing value. In this section, we see a simple way to do this with the function on.
    🔗
    trigger1 = on(x) do x
    println("New value of x is $x")
end
    If you evaluate the code above, you will see ObserverFunction defined at... Again, not very interesting. However, any time that the variable x is updated, a line will be printed out. Running
    🔗
    x[] = 4
    This will result in the output:
    New value of x is 4
    🔗
    And if this is updated many times like in the following for loop:
    🔗
    for i=1:5
  x[] = i
end
    And the result of this is:
    New value of x is 1
New value of x is 2
New value of x is 3
New value of x is 4
New value of x is 5
    🔗

    Warning 16.6.

    Careful using the on function with Observables. If it is run more than once, then the code will be run each time. In a code block or script that is only run once, this is fine, but often in a julia notebook, a cell might be run multiple times.
    🔗
    🔗

    Multiple Triggers.

    An Observable can have multiple triggers. If we add
    🔗
    trigger2 = on(x) do x
  println("Another trigger.  x: $x")
end
    And then the observable is updated with x[] = 10, then both of the triggers are fired and the result is
    New value of x is 10
Another trigger.  x: 10
    🔗
    If you have assigned a trigger with the on function to a variable, like above, we can remove that trigger with the off function. For example,
    🔗
    off(trigger)
    If then we update the value of x, say we x[] = 6, then we get the output
    New value of x is 6
    🔗
    The second trigger is not fired.
    🔗
    🔗
    🔗

    Subsection 16.2.2 Finding Values of Observables

    If we want to use the value of an observable, if we try to do it with 2*x as an example, then we get the following:
    MethodError: no method matching *(::Int64, ::Observable{Int64})
    basically indicating that we can’t do standard operations with Observables. There are two ways to do this. First, using the syntax 2*x[] will multiply the value of x by 2, returning 12.
    🔗
    Alternatively the to_value function will look up the value of the Observable or if the argument is just a number or string, return that string. For example, to_value(x) returns 5 and to_value("hello") returns "hello". This implies that value_of can be used if you don’t know if a variable is a standard one or an Observable.
    🔗
    🔗

    Subsection 16.2.3 Chaining Observables

    A common need is to create a new observable based on a previous Observable. We can do this with the lift function. For example,
    🔗
    y = lift(x - > x^2, x)
    Then the output is Observable(36). That is y is a variable that is an Observable and the second argument, x notes that this updates when x updates. Therefore if we update x then y will be updated as well. Note that this is in lieu of using the on function above. Therefore,
    🔗
    x[] = 7
    This will trigger the on function that we have to echo: New value of x is 7, but if we evaluate y[], then the result is Observable(49).
    🔗

    The @lift macro.

    If we want a new observable that takes three other Observables and makes a function from them, say with
    🔗
    a = Observable(1.0)
b = Observable(6.0)
c = Observable(10.0)
mean(a,b,c) = (a+b+c)/3
m = lift(mean,a,b,c)
    The result is Observable(5.666666666666667). To make the lift function a bit shorter, lines 4 and 5 can be replaced with
    🔗
    m = @lift(($a + $b + $c) / 3)
    where each of the observable values are preceded with a $, which is common for variables inside of macros.
    🔗
    🔗

    Example 16.7.

    Create an animation of the surface plot \(z=sin(x^2+y^2-t)\) for \(-\pi \leq x,y \leq \pi\) and \(0\leq t \leq 10\text{.}\)
    🔗
    Solution.
    The following code will produce this:
    🔗
    grid = range(-pi, pi, length=100)
xs = [x for x in grid, y in grid]
ys = [y for x in grid, y in grid]
time = Observable(0.0)
zs = @lift sin.(xs.^2 .+ ys.^2 .- $time )
fig = Figure()
ax = Axis3(fig[1, 1],
  limits=(-pi, pi, -pi, pi, -1, 1),
  title=@lift("t = $(round($time, digits = 1))")
)
surface!(ax, xs, ys, zs)
timestamps = range(0, 10, step=1 / 10)
record(fig, "../../assets/plots/animations/sine-wave.mp4", timestamps; framerate=30) do t
  time[] = t
end
